# Agent 产出物管理层（Agent KM）：调研与设计文档

日期：2026-07-15
来源：基于 GitHub Trending 调研引发的完整产品推演
状态：交付

---

## 一、起点：趋势判断

对 GitHub Trending 日/周/月三份榜单（约 50 个项目）的调研显示，开源社区的重心已从"用 LLM 做应用"转向"给 Agent 建操作系统"：记忆层（cognee、codebase-memory-mcp）、沙箱（CubeSandbox）、模型网关（OmniRoute）、多 Agent 编排（orca、herdr）、感知与执行工具（Agent-Reach、page-agent、OfficeCLI）全线爆发。

框架化理解：LLM 是大脑，价值正转移到接口层——感知（输入）、执行（输出）、记忆、安全边界、协调。模型本身趋于商品化，媒介和管线成为稀缺。

进一步分析发现：榜单在堆"能力"，空缺集中在"信任"——评估与可观测性、权限与身份（Agent 的 IAM）、可靠性与回滚（Agent 的事务系统）、记忆质量管理、人机交接协议。这与云计算早期"先有算力、后有 IAM 与监控"的演进规律一致。

## 二、问题定义

**核心问题：Agent 产出物没有管理层。** 各 Agent（Claude Code、Codex、Cowork 等）产出的文件散落在会话和文件夹中，缺失四样东西：

溯源（这份文件是哪个 Agent、哪次任务、基于什么输入产出的）；版本取代关系（新版覆盖旧版，避免脏引用）；生命周期（草稿/交付/被取代/过期）；跨 Agent 引用（权威存储 + 引用，而非复制粘贴）。

问题有对称的两面：写入侧是"管好产出"，读取侧是"装配上下文"——新会话该读哪些历史产出物。两侧必须是同一个系统：读取时的排序质量完全依赖写入时的元数据。合起来是"Agent 的文件系统"：产出物存储是硬盘，上下文窗口是内存，缺的是中间的调度器。

关键约束：元数据必须自动产生。人不会手动登记文件，Agent 同理——捕获必须内嵌在产出动作里，不能依赖自觉。

## 三、可行性调研结论

需求证据充分：行业报告显示规模化部署 Agent 的组织在头三个月内即遭遇产出物管理瓶颈；claude-mem（8.4 万星）验证了跨会话上下文痛点的强度，也验证了"hook 自动捕获 + 索引 + 渐进检索"架构的可行性（token 消耗可降约 10 倍）。

竞争格局呈两端拥挤、中间空缺：Cloudflare Artifacts（2026 年 4 月 beta）占据存储+版本层（Git 兼容的 Agent 文件系统）；claude-mem 及记忆框架（mem0/letta/zep/cognee）占据过程记忆层。**无人占据中间的语义层**：产出物的溯源、取代关系、生命周期、任务驱动装配。

风险：平台方（Anthropic/Cloudflare）可能原生做掉此层，窗口期估计 6-12 个月。claude-mem 的先例说明快速进入社区可在被吞并前建立事实标准。

## 四、类比框架：从 Java/Go 生态史借鉴

对 Agent 生态与 Java/Go 框架演进史的类比得出几条可操作结论。

当前处于"EJB 时代末期"：LangChain 类重框架遭遇反叛，裸调 API 是暂时回退，最终赢家将是抽象恰到好处的"Spring"。MCP 正在扮演 JDBC 角色——接口标准比实现值钱；同时警惕 SOAP 式的过度标准化。Go 的教训适用于基础设施层：小接口 + 组合优于大框架。两个"必然到来"的时刻：skills 依赖管理的 go mod 时刻、项目约定的 Spring Boot 时刻。可观测性永远迟到但必然到达——现在补信任层等于 2010 年做 APM。

**本产品对应的历史位置是 Maven**：标准坐标（namespace:name:version）、POM 元数据（溯源）、仓库（权威存储）。Maven 赢 Ant 靠的是约定而非技术——先定约定，工具是约定的执行者。

类比的三处失效即设计难点：Maven 元数据是人写的，我们的必须自动；jar 是确定性构建，Agent 产出是概率性的，版本取代不能只靠时间戳；Maven 依赖是精确声明的，Agent 的相关性是模糊的——所以形态是"Maven + 搜索引擎"：坐标管权威性，检索管发现性。

场景定位对照 Maven 三层仓库：本地仓库（个人）→ 私有仓库（团队）→ 中央仓库（公开）。企业 95% 的价值在前两层；公开层已被 skills 市场占位，永远不做。这决定了产品是个人/团队工具：无网络效应可蹭也不需要（单机价值成立），隐私优先既是约束也是对抗云厂商的差异化。

赛道选择上，与"skills 冲突管理"对比后选定产出物管理：依赖解析历史上必被平台收编（go mod 杀死 dep），而仓库+元数据层有第三方存活先例（Maven 属 Apache，Nexus/Artifactory 独立发展多年）；且产出物库有资产积累性——溯源图谱随使用复利增值，冲突解决器不沉淀任何东西。

## 五、架构设计

设计思想四条：从 Go 借"小接口 + 库优于框架"（卸载后文件依然完好）；从 Maven 借"约定优于工具"；从 Spring 借 AOP 无侵入拦截与合理默认值；从 Python/Git 借人肉可读的简单数据结构。

六层架构，依赖单向向下：

```
L5 接口层    MCP Server（register/search/get，不超过五个工具）+ CLI
L4 装配层    Resolver：任务 → 相关产出物，渐进式披露
L3 索引层    SQLite 全文索引（可丢弃、可重建的缓存）
L2 元数据层  Manifest：坐标 / 溯源 / 生命周期 / 摘要
L1 存储层    普通文件 + 内容寻址版本链（真相所在）
L0 捕获层    Hooks 拦截写入
```

核心原则：真相放在人肉可读的文件里，语义放在约定好的元数据里，智能放在可丢弃的索引层里，捕获用无侵入切面，接口保持最小且标准。

宿主适配现状（2026 年 7 月核实）：Codex CLI hooks 已稳定（v0.124.0 起，含 post-edit 事件）且 MCP 原生支持；ZCode（Z.ai 桌面端）完整支持 MCP 并兼容 Claude Code 插件市场；Claude Code 全支持。hook 正在成为行业标配，各家互相兼容插件格式。因此 MVP 收缩为两件东西：一个 MCP server + 一份 hook 脚本（同一脚本适配 Claude Code 与 Codex，插件市场分发，ZCode 顺带覆盖）。watcher 守护进程、向量检索、菜单栏 app 全部砍掉，留待真实抱怨出现后再做。

## 六、正反方评审结论（子 Agent 独立论证）

正方最强论点：周期性任务"接着上次做"、数据口径一致性（防止"两份数字打架"）、"final_v2"事故防治；hook 的原理性优势（溯源信息只在生成那一刻存在）；零习惯改变。

反方最强论点：90% 税收问题（Agent 一次任务写二三十个文件，九成是中间产物，为 10% 的交付物对 100% 的写操作收税）；sidecar JSON 污染目录（复刻 .DS_Store）；**完整性悖论（最致命）**——Maven 成立靠强制环节（不发布拿不到依赖），外挂 hook 的登记是旁路可绕过的，不完整的记录系统不会退化成部分有用，而会退化成不被信任，被坑两次用户即回到 grep，此时成本照收、收益归零。

裁决：完整性悖论攻击的是架构而非执行，但也指出出路——强制力应来自读取侧而非写入侧。双方共识：取代关系宁可留空不要瞎猜（错误的溯源比没有溯源更害人）；先做零成本约定实验再写代码。

## 七、边界推演与设计修正

将问题推演至一般形式："跨越有限工作记忆的多个片段，外化再内化状态"。人类文明用文字+制度解决过（口述→文字→索引→数据库），计算机用存储层级+虚拟内存解决过，human-AI 协作正处于空白地带——RAG、记忆框架、compaction 都是各自为战的临时分页器。

chat 场景的延伸分析：对话是工作记忆、产出物仓库、交互日志三者的混合体，这是注意力退化和内容无法复用的共同病根。Agent 用户的产出至少落成文件，chat 用户的产出物连独立存在都没有。平台的 memory 功能记"关于用户的事实"而非"对话的产出"，Artifacts 功能缺跨对话索引。此场景插不进 hook，属平台地盘，不做，但其洞察（蒸馏时刻）反哺设计。

真正新颖的只有三点：自动蒸馏的经济学（AI 生产成本降两个数量级，人类 KM 靠"写作成本高"完成的筛选失效，蒸馏必须自动化）；机器互读的格式（机器写、机器读、人审计，摘要是检索键不是简介）；概率性溯源（从署名变成信任校准）。另有反面边界：遗忘是功能不是缺陷——"什么都留下找不到"与"什么都留不下"信息论等价。

由此得出四条设计修正：

**修正一（最大）：摘要从写入时移到会话结束时。** 写入时 hook 只做零成本确定性记录（路径、会话 ID、时间戳），不调 LLM；会话结束（Stop hook）带全会话后见之明做一次蒸馏——什么是交付物、结论是什么、否掉了什么及为什么。同时化解"90% 税收"与"写入时摘要半瞎"两个批评。登记所有，蒸馏少数。

**修正二：蒸馏物升格为一等对象。** 会话蒸馏产出"会话摘要条目"（决策及理由），与文件条目共享同一索引和坐标体系。与 claude-mem 的分界：它记录过程观察，我们登记结果。

**修正三：溯源改造为信任校准。** manifest 增加 verified 字段（人确认过——采纳、交付、明确认可）与生成来源；检索按相关性 × 可信度 × 新鲜度排序。

**修正四：遗忘做成机制。** 蒸馏未提及的条目沉降为临时层；交付物 N 天未被检索自动标 stale 并降权；被检索且被采用的条目获得强化——用进废退，索引有新陈代谢。

**完整性悖论的正面回答：读取侧即强制力。** 不追求写入侧 100% 拦截，而是让新会话的上下文装配只从索引取料——没登记的文件不是被禁止，是不被想起。登记从义务变成入场券，这才是 Maven"不发布拿不到依赖"的真正对应物。

修正后最小闭环：写入时静默记录 → 会话结束蒸馏 → 检索时按相关性×可信度×新鲜度装配 → 使用反馈强化或衰减。

## 八、定性：Agent 版知识管理（KM）

本产品是 Agent 版 KM。这个定性的力量在于：KM 理念三十年未错，反复失败于两个人性顽疾——捕获成本（知识在人脑里，外化靠自律）与激励错位（写文档利他不利己）。Agent 版恰好消解两者：捕获免费（hook 是代码），激励闭环（写入者与受益者是同一人的下一次会话）。

KM 失败反模式对照（据文献）：

免疫的（人性坑）：激励错位、专家瓶颈、领导层与文化缺位、变革管理失败。

照样暴露的（结构坑）：内容腐烂（头号敌人，衰减机制只能缓解不能根治）；质量→信任死亡螺旋（蒸馏质量是命门，赌注从人的自律换成模型的判断力）；把存储当知识（登记≠蒸馏，警惕 JSON 格式的坟场）；碎片化（多宿主覆盖缺口）。

生死线不在采用，在内容质量的持续性。

## 九、应用场景（按契合度排序）

判断标准：产出物复用率 × 任务周期性 × 口径一致性要求。

1. **内容创作者/自媒体（最高，冷启动首选）**：选题调研增量更新、防自我重复、人设口径一致；几乎不用 git，无既有兜底方案。
2. **独立研究者/分析师/咨询**：月度扫描、清洗脚本、口径定义，复用与一致性要求顶格，人群较小。
3. **开发者（基本排除）**：程序员的会话串行相关性其实极高（同一代码库），但 git 就是那个成熟的 artifact 层——commit 即登记、blame 即溯源、merge 即取代、review+CI 即 verified。真实缺口是未落进 git 的残余物（决策理由、死胡同、代码库理解），而这块已被 claude-mem 类工具占据。结论：不是没需求，是需求形状不同且已有人在填。唯一裂缝是 vibe coding 的非程序员——写代码但不会用 git，行为模式接近创作者，人群在膨胀，值得留意。
4. **小团队知识交接（第二阶段）**：价值最大但依赖个人层跑通；引入共享后组织类 KM 反模式部分复活，届时重过反模式清单。
5. **个人生活/泛用途**：不做。

冷启动画像："一个人 + 高频 Agent 使用 + 产出物就是生计"。

## 十、价值叙事的压力测试与修正

压力测试："大多数人的使用模式是用 AI 完成任务，任务完成会话即结束"——这个观察成立，且必须正面吸收。

承认：多数会话是终点式的，价值当场兑现，不需要留下任何东西。设计已接受这一点（遗忘是默认，蒸馏是例外），强行留痕即坟场。

定位修正：产品不面向"大多数人"，只面向任务**串行相关**的少数人（创作者、分析师、持续项目）。对他们而言"任务完成"只是章节结束，不是书结束。一次性任务用户不是市场，这是定位而非缺陷。

归因洞察：正因会话在任务完成时结束，丢失的代价不在当下发生——它三周后以"重新推导"的形式出现，且被用户误记账为"反正 AI 快，重跑一次"。痛点真实但归因隐蔽，这解释了为何市场无人喊。

**核心叙事收窄**：重跑成本随模型进步持续下降，"省时间"的价值叙事会被蒸发。产品长期站得住的理由是两样重跑买不回来的东西——**一致性**（重跑出的脚本口径与上次不同，两份数字打架是重跑的固有属性，不是速度问题）与**已验证的结论**（上次的结论经人工核实、采纳、对外交付；重跑产出的是 verified 位归零的新东西）。弱叙事"帮你找回上次的文件"废弃。

## 十一、分发策略：目标用户与渠道的错位及修正

裂缝：首选人群是"不用 git 的人"，但 GitHub/Trending/插件市场是开发者渠道——照搬 claude-mem 路径会精准触达被排除的人群。

三层修正：

**第一层（冷启动）**：人群再收窄一格为 **AI-native 创作者/分析师**——各自人群中技术浓度最高的一撮，装得动插件、看得懂教程。纯小白容错率低，产品糙时来了只会流失，本不该是第一批用户。

**第二层（核心渠道）**：创作者不逛 GitHub，但重度消费 AI 工具类内容——推特/YouTube/小红书/newsletter 上的工作流教程就是这个人群的 Trending。结构性优势：**目标用户即内容生产者，工具解决真问题会自发变成他们的选题**。GitHub 的角色是可信度背书与基础设施（如 ffmpeg 之于剪辑教程），不是发现渠道。

**第三层（未来下沉）**：Cowork/Claude 桌面端的插件市场与连接器目录是非技术用户的应用商店，安装动作是点一下而非 git clone。平台市场的成熟速度决定下沉时机，也给了产品打磨窗口。

顺序不可反：第一天追求小白可用，包装与支持成本会压垮 MVP。

## 十二、当前行动

代码之前先跑零成本实验：已产出《Agent 产出物约定》（agent-artifacts-convention.md），核心为目录约定（artifacts/ 与 tmp/ 分离）、命名约定（日期-主题-类型，禁 _v2 后缀）、INDEX.md 登记（摘要写结论、状态标草稿/交付/已取代、来源一句话）、读取约定（先读 INDEX，忽略已取代，复用优先于重造）。

跑一个月观察三项指标：Agent 遵守登记的比例（验证完整性悖论）；INDEX 摘要在新会话中的实际使用率（验证读取侧价值）；仍靠 grep/人肉回忆兜底的时刻（即约定覆盖不了、值得写代码的 20%）。

实验结论决定下一步：约定覆盖 80% 需求则维持轻方案；不够用之处即 MVP 的精确需求清单。

## 十三、第二轮推演：中立层定位与共享设计

### 定位升级：跨厂商中立层

核心价值主张升格为：**换模型不丢积累**。产品形态为跨 Agent 插件（一个 MCP server + 每宿主薄适配器），同一本地存储渲染成各家原生格式注入（CLAUDE.md / AGENTS.md / 记忆接口）。

这一升格把"平台吞并"从死穴反转为护城河：各平台必然自建记忆/产出物层，但每家建的都是自家围栏内的——制造锁定是平台的本能，**反锁定只能由第三方做**，这是结构上无人能抢的位置（先例：1Password 在各浏览器均内置密码管理的情况下靠跨平台存活壮大）。时机顺风：模型层商品化、多模型混用常态化，切换越频繁，"积累绑定单一厂商"越痛。存量在哪，议价权在谁手里。

中立层的信任负担随之翻倍："数据永远是用户能 grep 的普通文件"从设计原则升格为对外承诺。范围克制：光谱左端（产出物、结论、决策）为主体，偏好声明顺手装，流程/技能只存引用不存实现——与 Hermes 类产品做邻居不做对手。

**与 Hermes 的对照**（架构验证 + 语义分界）：Hermes 已实现同一底盘（会话结束自动蒸馏、SQLite FTS + 摘要、按需加载），蒸馏对象是流程（程序性记忆）；本产品蒸馏结果（陈述性记忆）。生命周期语义相反：技能越用越好（复用即强化），产出物越放越旧（复用前查新鲜度与取代）。判断"结果>流程"的长期依据：通用流程被模型迭代持续吸收（技能库随模型升级贬值），而"你的历史事实"不在任何权重里；且流程正退化为偏好声明——光谱右端向左端塌缩。护城河不在蒸馏动作（已通用化），在特定内容类型的元数据语义深度。

### 公开层改判：从"永远不做"到"晚做，格式先行"

原判断"公开层已被 skills 市场占位"只对一半：skills 市场分发的是流程，**无人分发带元数据语义的沉淀内容**（结论库、决策框架、验证过的调研）——这一格是空的。Maven 三层至此完整：本地仓库（个人）→ 私有仓库（团队）→ 中央仓库（公开知识包）。

公开层补上了个人工具缺失的增长循环：创作者用工具积累 → 打包知识包分享/售卖 → 受众为加载包而安装工具 → 新用户积累 → 部分成为新发布者。"用户即渠道"从内容营销升级为产品机制，并给目标人群一个直接变现理由（最硬的采用动机）。

节奏不变：一期个人账本、二期团队、三期公开包。但 **manifest 格式今天就须含 namespace 与 verified_by**——格式改不动时生态已长在上面。

### 信任模型修订

- `verified: bool` 改为 `verified_by: [身份]`——验证位不可传递，她验证过 ≠ 你验证过
- 第三方内容永远带命名空间（坐标系 namespace 在此兑现，即 Maven groupId），默认低信任层级，与用户自己验证的内容物理分区，检索时明示来源
- 冲突浮出而非静默覆盖：矛盾条目并排呈现、各带溯源，用户裁决

### 导入审查机制：导入即 PR

外部内容包不直接入账本：先进暂存区 → Agent 审查 → diff 报告 → 用户裁决 → 合并。git 心智模型复用：导入=分支，自检=CI，裁决=merge commit。

三类检查（成本从低到高）：包内质量（缺溯源、时间戳过旧、内部矛盾，相当于 npm audit）；重叠（与账本说同一件事，去重合并双来源）；冲突（与用户 verified 条目矛盾，并排呈现裁决）。

裁决四态：采纳（入第三方命名空间）、采纳并背书（verified_by 加签）、拒绝、搁置隔离。

实现要点：冲突检查引擎即已有的"取代关系判定"批量化，无新原语；大包渐进审查（先摘要层，仅对疑似冲突子集深检）；审查质量依赖自身账本成色，反向强化遗忘机制的必要性。审查报告本身是体感时刻（"3 条冲突、7 条比你的新、12 条你没有"）。

### 结果与过程的角色分工

**结果是资产，过程是质保书。** 账本主体是结果；每条结果挂一层过程残余（溯源），存在目的不是复用而是信任校准。用户 99% 的时刻只消费结果，过程仅在三个信任边界时刻被翻出：结果可疑（审计）、需要复现改编（看方法）、导入裁决（过程即证据）。

设计铁律：**过程永远不进前台**——检索结果只出现结论与状态，溯源折叠在"展开审计"一步之内。共享场景同理：知识包卖的是结论，撑起可信度的是可见的过程；方法作为商品是教育生意，不与账本生意混淆。

## 十四、技术架构（含后期功能预埋）

### 核心决策：CLI 内核 + 薄适配器（git 模式）

关键修正："为什么要用 MCP"的反问成立——Claude Code 优先的第一版不需要 MCP：写入靠 hook（PostToolUse/Stop），注入靠 SessionStart hook，会话中检索由 Agent 直接执行 CLI。MCP 的不可替代价值在 GUI 宿主（无 hook，MCP 是唯一扩展点）与跨宿主标准化，故降级为 1.5 期适配器。

全部逻辑收进单一可执行 `akm`，宿主适配全部薄壳：Phase 1 = Claude Code hooks（几行 shell 调 akm）；Phase 1.5 = MCP server（包装 search/get，覆盖 Codex/Cowork/ZCode）；Phase 2 = 团队同步（git remote，内核不变）；Phase 3 = 导入审查/公开包（内核预留的 Reviewer 启用）。内核对宿主零假设——中立层定位在代码层的兑现。

### 存储布局（两轮修正后）

修正一（采纳 sidecar 批评）：集中式元数据，不做 sidecar。修正二（定位对齐）：**账本全局唯一，项目降级为作用域**——照抄 Maven ~/.m2 模式：所有项目的条目在同一账本靠坐标寻址，项目里只有声明没有数据。理由：资产是人的积累而非项目附件；结论天然跨项目；首选人群没有 repo；按 repo 存放会让团队共享变成 commit 的副作用，导致会话溯源不经意进公司仓库。

```
<用户选定的可见位置>/akm-ledger/   # 真相层。init 时用户选，推荐 ~/Documents 或网盘同步文件夹
  journal/                         # L0 原始记录，append-only
  entries/                         # 结论型条目正文（md）
  manifests.jsonl                  # 全部元数据，git diff 友好
~/.akm/                            # 缓存层：config、index.db（可重建）、访问统计
<project>/.akm                     # 极小标记文件：项目身份+局部配置，可进 git，不存数据
```

原则：**真相可见，缓存隐藏**。账本住可见位置的理由：隐藏目录在换机迁移中最易丢失，用户最值钱的资产不能住在搬家会被落下的地方；可见性即可信度（Obsidian vault 同款心智模型）。文件型产出物永不搬家——账本只存路径+内容哈希，移动靠哈希重关联。代价如实记录：项目交接不再自动携带上下文，需显式导出（换来隐私与账本统一性）。

### 同步策略（三档递进，真相永远是文件）

1. **零配置**：账本放网盘同步文件夹（iCloud/Dropbox），多设备免费
2. **一条命令**：`akm sync` git 模式——蒸馏后自动 commit+push、SessionStart 自动 pull；对创作者完全隐藏 git 词汇（只见"开启同步/已同步"）；副产品是账本自身的版本历史——知识何时加入、何时改判，git log 全记录（溯源之上的溯源）
3. **团队期（P2）**：共享 remote + 每人 namespace + Reviewer 审查合并，同一 git 机制升级，共享是显式发布而非 commit 副作用

**热数据分家**：last_accessed / access_count 高频变动，移出 manifests.jsonl 入本地缓存层（每设备一份，读取时合并），避免同步噪音与冲突；丢失仅影响遗忘机制精度，可容忍。

**数据库定位**：拒绝作为真相层——被囚禁的数据违反"删掉工具剩下可 grep 文件"的根本承诺；允许作为索引缓存（index.db 本就是 SQLite）与团队服务端内部实现，对外边界永远说 md+jsonl。

### 数据模型（字段先行，逻辑后置）

```
Entry {
  id:           内容哈希（内容寻址，天然去重）
  coords:       namespace/name@version    # namespace 默认 "self"，为导入/团队预留
  type:         file | conclusion | decision | preference | skill-ref
  status:       draft | final | superseded(→id) | stale | quarantined  # quarantined 为导入预留
  summary:      蒸馏产出，给机器的检索键
  provenance:   { host, session, task_digest, inputs[], model }
  verified_by:  []          # 第一天即数组，为共享预留
  scope:        session | project | user   # 为作用域/GC 产品线预留
  created / last_accessed / access_count    # 遗忘机制原料；访问统计存缓存层（见同步策略）
}
```

Phase 1 代码对 namespace≠self、quarantined、scope 只读不写，格式定死，后期零迁移。

### 六个内核组件与阶段归属

1. **Capture**（P1）：hook 触发，journal 追加一行，零 LLM 零阻塞——关键路径上的代码必须笨
2. **Distiller**（P1）：Stop hook 触发，读 journal+会话记录产出 entries；LLM 经子进程 `claude -p` 调用（复用宿主登录，零 API key），provider 抽象为接口（distill/judge 两方法）
3. **Index/Search**（P1）：SQLite FTS5，`akm rebuild` 全量重建——索引永远是缓存
4. **Hydrator**（P1）：SessionStart 注入 top-N 摘要，硬性 token 预算上限——读取侧是入场券不是税
5. **Reviewer**（P1 存在，P3 全量启用）：取代关系判定引擎；P1 判定新旧条目取代，P3 批量化即导入审查——一个引擎两阶段用
6. **Sync**（P2）：账本天然 git-able，团队=共享 remote+每人一 namespace，合并冲突走 Reviewer，不自建同步协议

### 有意不做

守护进程（事件驱动，hook 拉起跑完即退）、向量检索（FTS+好摘要，条目过万再议）、自有同步/账号（git 与文件系统即同步层）、UI（CLI 输出 markdown，报告由 Agent 转述）。

自检标准：**删掉 akm，用户剩下装满 markdown 和 jsonl 的普通文件夹——损失的只是便利，不是数据。**

### TypeScript 工具链

- 运行时/打包：bun，`bun build --compile` 出单二进制（用户无需 node 环境）；`bun:sqlite` 内置 FTS5，索引零外部依赖
- MCP 适配器：官方 `@modelcontextprotocol/sdk`
- Schema：zod 定义 manifest，一份 schema 生成校验器与文档
- LLM 调用：`claude -p --output-format json` 子进程，结构化输出直接 parse
- 仓库：monorepo 四包——core（纯逻辑）、cli（薄壳）、mcp（薄壳，1.5 期）、plugin-claude-code（hooks+安装，插件市场分发）
- 测试：golden 夹具（journal 进、entries 出），mock LLM 后蒸馏管线确定性可单测——record-replay 思想自用

`akm init`——初始化 .akm 结构 + 安装 Claude Code hooks，随后按 Capture → Distiller → Hydrator → Search 顺序实现。
