# 我如何用 akm：让 Claude Code 记住三周前的调研

> 教程即分发。这篇写给和我一样"产出物就是生计"的人：内容创作者、独立研究者、天天让 Agent 干活的人。

## 我的痛点

我用 Claude Code 做选题调研。每次会话它都干得不错——产出调研文档、否掉几个方向、定下口径。然后会话结束，一切归零。

三周后我说"接着上次的选题做"，它重新调研一遍。快是快，但两个致命问题：

- **口径漂移**：这次的统计范围和上次不一样，两份数字打架，我自己都不知道信哪份
- **已验证的结论归零**：上次我人工核实过、真发出去过的结论，这次变成一个未经验证的新推导

重跑买不回**一致性**和**已验证**。这是我装 akm 的原因。

## 装好之后发生了什么

装完 `akm init` 之后我什么都没改。照常开会话干活。

**第一个会话**：做了一次选题扫描，写了 3 个文档。会话结束时 akm 的 Stop hook 自动蒸馏——它从 45 次文件写入里挑出 2 个真正的交付物，外加登记了 1 条决策："押方向 A，放弃方向 B（头部已占位）"。我没写一个字的文档。

**三周后的会话**：开场 Claude 直接说"你的账本里有上次的选题扫描（方向 A，已验证）和一条相关决策"。它接着上次的口径做增量，而不是从零推导。旧版调研自动标记"已取代"，我永远不会误引用老数据。

**误引用防治**：有次我搜到一条三个月前的结论，akm 给它标了 `/stale`（30 天没人碰过，已降权）。提醒我先核实再用——而不是让我在不知情的情况下引用过期口径。

## 我常用的三条命令

```bash
akm search 选题     # 找历史产出物：新的、已验证的排前面，已取代的直接不出现
akm get <id>        # 看全文+溯源：哪个会话、基于什么输入产出的
akm status          # 每周看一眼账本健康：多少条结论、几条过期该处理
```

## 它不做什么（这很重要）

- 不碰你的文件——产出物在哪就在哪，账本只记路径和哈希
- 不记录纯聊天会话——没写文件的会话零开销零入账
- 不猜——新旧版本关系拿不准时，它宁可不标，也不给你错误的溯源
- 不绑架数据——`akm uninstall` 之后，账本还是一个普通文件夹，md 和 jsonl，随便 grep

## 一句话总结

akm 是 Agent 的记账员：你干活它记账，你失忆它提词。装一次，之后唯一的感知就是——新会话突然"记得"上次干了什么。
