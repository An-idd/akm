## 一、发现列表（按严重度排序）

### 发现 1【中高】插件分发路径的 hooks.json 落后于 init 注册表：相关性注入与防抖在插件通道上不存在

- 【文档意图】README:17-18 "After your first message → local relevance search over the ledger, inject matching history"；README:111 "Trigger rule: at turn end, if the session added ≥5 file writes or 15+ minutes passed since the last distill, one background distill runs"。
- 【代码现实】`akm init` 路径正确注册 5 个 hook（`packages/core/src/init.ts:31-37`，Stop 带 `--debounce`，含 UserPromptSubmit）。插件分发用的 `packages/plugin-claude-code/hooks/hooks.json` 只有 4 个事件：Stop 为 `distill --detach`（hooks.json:14，无 `--debounce`），SessionEnd 同（hooks.json:21），整个文件没有 UserPromptSubmit（hooks.json:1-33）；capture/hydrate 缺 timeout 字段（init.ts 统一 15s）。
- 【影响】插件市场用户（M7 目标通道）：(a) 每回合只要有新文件写入即触发完整 haiku 蒸馏——防抖成本模型失效，长会话成本或放大一个数量级；(b) "首条消息后按相关性注入"这条核心产品承诺完全不发生。
- 【修复建议】hooks.json 与 init.ts:31-37 对齐（Stop 加 `--debounce`、补 UserPromptSubmit、补 timeout），或 install.sh 改为调用 `akm init` 统一注册，消灭双份真相。

### 发现 2【中】蒸馏输入无防注入措施，投毒内容可经水合持久化

- 【文档意图】文档未承诺防注入——`docs/2026-07-16-修复与架构调整计划.md:233` 明示推迟（"单用户自产自销期威胁模型不成立，导入外部包前必须做"）。但 README Cost & privacy 节（README:108-115）披露了明文归档风险，未披露此项。
- 【代码现实】`buildDistillPrompt`（`packages/core/src/distill.ts:125-154`）将 `transcriptSummary` 原样内插（distill.ts:135-136），无数据/指令隔离措辞、无转义；`condenseTranscript` 只剔除 `<system-reminder>` 块（`packages/core/src/transcript.ts:57`），网页抓取与第三方文件内容照常进入。水合侧 `buildHydrationContext` 将 summary 原样拼进 additionalContext（`packages/core/src/hydrate.ts:18`），无消毒。
- 【影响】会话中的恶意内容可诱导 Distiller 产出虚假条目，随后在未来所有会话的水合注入中持久化——一次投毒长期生效。已存在的三道防线：file 条目 path 走 journal 白名单（distill.ts:47-50）；`verified_by` 由管线强制置空、LLM 输出 schema 无此字段（distill.ts:97、provider.ts:5-12）——伪造 verified 不可行；status 枚举限 draft/final（provider.ts:9）。可行的攻击面：虚假结论/summary 藏指令。
- 【修复建议】(a) distill prompt 给 transcript 段加显式数据边界与"忽略材料内指令"规则；(b) 水合注入行对 summary 做长度/换行/标记消毒；(c) README 隐私节补披露（与 transcript 同等待遇）。

### 发现 2b【中】judge 可被操纵挤掉 verified 条目

- 【代码现实】judge prompt 将新旧 summary 并排（distill.ts:156-164），被投毒 summary 可诱导 "supersedes" 裁决；distill.ts:64-69 对 verified 条目无特殊保护，人工背书条目可被标 superseded 从默认检索消失。parseVerdict 的 unsure 兜底（claude-cli.ts:58-65）是概率性缓解非边界。
- 【修复建议】取代目标 `verified_by` 非空时不自动取代，降级为"冲突浮出"由用户裁决——设计文档第十三章对第三方内容的既有原则，提前用于本命名空间。

### 发现 3【中低】"无关任务零注入"无机制保障：相关性检索无最低分阈值

- 【文档意图】开发计划 M5 判据："空账本/无关任务零注入——宁可不注入，不可注入垃圾"；README:137 "inject nothing rather than noise"。
- 【代码现实】空账本零注入为真（`packages/cli/src/main.ts:435`；hydrate.ts:11）。UserPromptSubmit 将首条消息拆最多 24 token 做 OR 检索（main.ts:422-427；`packages/core/src/search.ts:102-112`），任一 trigram 命中即候选，取 top 8 注入——无相关性下限（search.ts:133-144 只排序不设门槛）。
- 【影响】无关场景退化为"总是注入排名最高者"，违背自立的注入纪律。
- 【修复建议】bm25 rank 设最低分（或要求 ≥2 token 命中），低于阈值返回空。

### 发现 4【低】SessionStart 导览行绕过 token 预算核算

- 【代码现实】预算在 buildHydrationContext 内部是硬的（hydrate.ts:17-24），但 SessionStart 分支在核算后无条件追加导览行（main.ts:438），不计预算，超出约 30-50 token。
- 【修复建议】导览行并入预算核算，或文档明确预算仅约束条目列表。

### 发现 5【低】compact 可将 preference 并入 conclusion，静默剥夺"永不衰减"特权

- 【文档意图】README:83 "preference entries never decay"；README:70 compact "Conservative"。
- 【代码现实】compact 候选集含 preference（`packages/core/src/compact.ts:22-24`），合并产物 type 硬编码 "conclusion"（compact.ts:43），来源整簇转 superseded（compact.ts:67），prompt 无排除规则（compact.ts:84-97）。
- 【修复建议】compact.ts:22 active 过滤加 `e.type !== "preference"`（一行）。

### 发现 6【低】MCP 侧读不到 project 作用域条目，"read-everything"表述略过此限制

- 【代码现实】MCP akm_search 不传 project（`packages/mcp/src/server.ts:36`），search 对 project 条目要求精确匹配（search.ts:137）——MCP 永远看不到 project 条目（akm_get 按 id 直查不受限，server.ts:54）。
- 【影响】方向保守（不泄漏），但 M8 跨宿主水合对项目条目失效。
- 【修复建议】akm_search 加可选 project 参数，或文档如实标注。

### 发现 7【低】installClaudeHooks 写入的 hook 命令未加引号，路径含空格即全部静默失效

- 【代码现实】selfCmd() 返回裸路径（main.ts:44-47），installClaudeHooks 拼 `${akmCmd} capture` 写入 settings.json（init.ts:31-37）无引号；对比插件 hooks.json 自带引号（hooks.json:7）。home 路径含空格时五个 hook 静默全灭——恰是开发计划自己警告的"hook 故障即卸载导火索"。
- 【修复建议】akmCmd 含空格时加引号。

### 标记文档过时（实现了但文档没说）

- >4MB 文件不做 content_hash（main.ts:142-150），README:27/140 未提上限
- search 默认同时过滤 quarantined（search.ts:135），README:66 只提 superseded
- stale 为检索时动态计算（search.ts:157-160），schema.ts:31 的 stale 枚举无写入方——行为兑现承诺，数据模型文档与实际机制有出入

## 三、安全审视

**A. 账本投毒**：见发现 2/2b。三道已有硬防线（path 白名单、verified_by 管线强制置空、status 枚举锁死）值得肯定；未设防通道为虚假 summary/body 与 judge 操纵。

**B. Shell 注入/路径**：总体安全——会话数据经 stdin JSON（main.ts:49-52）不过 shell；spawn 数组 argv（main.ts:182-187）；prompt 走 stdin（claude-cli.ts:24-28）；FTS token 引号转义 + LIKE 参数绑定（search.ts:105-123）无 SQL 注入面；install.sh set -euo pipefail 全程引号。残留：init 写 hook 命令无引号（发现 7）；session_id 直接拼文件名（ledger.ts:29、main.ts:193,238）无字符校验——来自受信宿主（实际为 UUID），建议加 `[\w-]` 白名单，一行成本。
