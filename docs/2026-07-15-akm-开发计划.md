# akm 开发计划

日期：2026-07-15
状态：交付
关联：《2026-07-15-agent-km-产品调研与设计.md》（架构依据见第十四章）
技术栈：TypeScript + bun，monorepo（core / cli / mcp / plugin-claude-code）
预估：M0–M7 约 4-5 周（可发布），M8 再加一周

---

## 里程碑（顺序即依赖）

### M0 脚手架（1-2 天）
- bun monorepo，先建 core / cli 两包
- zod 定义 Entry / manifest schema（namespace、verified_by、scope、quarantined 全部预埋）
- golden 夹具测试框架：journal 进、entries 出，mock LLM
- ✅ 判据：`bun test` 跑通一个空管线夹具

### M1 `akm init`（2-3 天）
- 交互式选账本位置（默认推荐 ~/Documents/akm-ledger），建目录结构，写 config
- 注册 Claude Code hooks（settings.json）；生成项目 `.akm` 标记文件
- 向上发现逻辑：cwd → 标记文件 → scope 判定，无标记落全局
- ✅ 判据：任意目录 init 后，新会话 hook 能被触发

### M2 Capture（2-3 天）
- PostToolUse hook：拦 Write/Edit 类调用，journal 追加一行（路径、哈希、会话 ID、时间戳）
- 零 LLM、性能预算 <10ms、写失败静默不阻塞宿主——关键路径上的代码必须笨
- ✅ 判据：真实会话 journal 完整记录所有文件写入，宿主无感知延迟

### M3 Distiller（1 周，最难）
- Stop hook：读 journal + 会话记录（~/.claude 会话 jsonl）
- provider 接口（distill / judge 两方法）+ `claude -p --output-format json` 实现
- 产出：文件条目（摘要、状态、溯源）+ 结论条目（决策及理由）
- Reviewer 引擎 v0：新旧条目取代判定，拿不准留空（错误溯源比没有溯源更害人）
- ✅ 判据：10 个真实会话 golden 样本，蒸馏产出人工评审通过率 >80%

### M4 Index / Search（3-4 天）
- SQLite FTS5 建索引（住 ~/.akm/cache），`akm rebuild` 全量重建
- `akm search`：相关性 × 新鲜度 × verified 排序，默认过滤 superseded，渐进披露（坐标+摘要 → `akm get` 全文）
- ✅ 判据：删 index.db 重建后结果一致；搜索延迟 <100ms

### M5 Hydrator（2-3 天）
- SessionStart hook：按当前 scope 过滤，注入 top-N 摘要，硬性 token 预算（默认 ~500，可配）
- 空账本/无关任务零注入——宁可不注入，不可注入垃圾
- ✅ 判据：新会话开场 Agent 主动提及相关历史产出物

### M6 生命周期（2-3 天）
- 访问统计入缓存层；stale 自动标记（N 天未检索）；`akm status` 账本健康报表
- ✅ 判据：构造过期条目，检索时正确降权并提示

### M7 打包分发（3-4 天）
- `bun build --compile` 单二进制；plugin-claude-code 包（hooks 配置+二进制安装）
- 插件市场发布；README + 一篇"我如何用它"教程（分发即内容）
- ✅ 判据：干净机器从安装到第一次水合 <5 分钟

### M8 = Phase 1.5：MCP 适配器（3-4 天）
- `@modelcontextprotocol/sdk` 包装 search / get / register 三工具
- Codex config 适配、ZCode 验证
- ✅ 判据：Cowork/Codex 检索到 Claude Code 会话沉淀的条目——跨宿主水合是中立层定位的第一次实证

## 贯穿任务

- 约定文件实验数据每周回流（遵守率、水合命中率、grep 兜底时刻），校准 M3/M5 设计
- M0 起持续积攒真实会话样本作 golden 夹具——蒸馏质量是产品命门，样本是命根子

## Backlog（P2/P3，不排期）

- `akm sync` git 模式（蒸馏后自动 commit+push，对创作者隐藏 git 词汇）
- 团队 namespace + 按作用域显式发布
- Reviewer 批量化 = 导入审查（导入即 PR：包内质量/重叠/冲突三检，采纳/背书/拒绝/隔离四态）
- 公开包格式（.akmpack：entries + manifests + 签名）
- `akm reconcile`：旁路写入的文件补录

## 主要风险

- **M3 蒸馏质量**：全产品的命门（KM 文献：质量→信任死亡螺旋）。缓解：golden 样本先行、判据设人工评审门槛、取代关系拿不准留空
- **hook 稳定性**：站在宿主关键路径上，故障即卸载导火索。缓解：静默失败、性能预算、journal 损坏可丢弃重来
- **平台 API 变动**：hook 接口年变数次。缓解：适配层薄、内核零宿主假设
